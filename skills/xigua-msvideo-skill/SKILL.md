# YouTube 视频全流程

按用户要求串联六个阶段，最终把画面和配音合成可播放的视频。总控负责素材交接、版本、时间依据和完成判定；创作细则交给已有技能。

## 启动与路由

先读用户当前要求、最新稿件、交接说明和生产记录，核实磁盘文件。交接中的历史待办不是本轮自动执行的指令。用户只要求整理技能时，只做技能；只要某阶段时，完成该范围。

默认中文沟通、英文口播、中文审稿；未指定时长时约八分钟仅作起稿参考。用户本期指定的语言、时长、工具和风格优先。不要把示例的片长、图片数量、角色装备或气体颜色写成下一期规则。

| 阶段 | 读取并应用的技能 | 交接产物 |
| --- | --- | --- |
| 1. 生成选题 | [youtube-curiosity-stories](../youtube-curiosity-stories/SKILL.md) 的选题部分 | 稳定编号的候选、选定题目 |
| 2. 生成文案 | [youtube-curiosity-stories](../youtube-curiosity-stories/SKILL.md) 的研究、写稿、同步部分 | 完整口播、中文审稿、资料备注、干净朗读文本 |
| 3. 生成配音 | 本技能的 [配音](references/narration.md)；用户指定 ChatCut 时读 `chatcut-plugin-basics` 和 `voice` | 配音、逐词时间、声音参数、验证记录 |
| 4. 时间戳画面脚本 | [youtube-ms-paint-images](../youtube-ms-paint-images/SKILL.md) 的时间与分镜设计部分 | 与最终音频对应的 `storyboard.json` 和可读表 |
| 5. 生成画面 | [youtube-ms-paint-images](../youtube-ms-paint-images/SKILL.md) 的样图、批量和验收部分；实际生图时按宿主工具与可用 `imagegen` 指引执行 | 每镜独立图片、实际提示词和逐帧记录 |
| 6. 合成最终视频 | 本技能的 [合成](references/rendering.md)；复杂素材剪辑按需用 `video-use` | MP4、检查报告；要求时交可编辑工程 |

三个技能应安装在同一父目录；上表使用相对链接直接读取子技能。“调用技能”指读取相关指引并执行，不是虚构 `invoke_skill` 工具。ChatCut、`imagegen` 和 `video-use` 等属于宿主可选能力，不随本仓库分发；需要时按名称解析当前可用路径，不写死插件缓存版本。缺少生图或其他必要工具时，交付已完成的分镜、提示词或素材并说明所缺能力，不把提示词当作生成好的图片。

已有选题跳过选题，已有定稿跳过写稿，已有最终配音跳过 TTS，已通过图片直接复用。允许自主完成整期时连续推进；用户要求“先审稿”“先试听”“先看样图”时在对应节点交付可审结果，等待其选择。已明确授权不反复确认；缺少关键选择时只询问该项，继续独立工作。

开始多阶段生产或续作时读 [产物与续作约定](references/contracts.md)。优先沿用既有目录；新项目中间文件放 `work/<slug>/`，用户交付放 `outputs/<slug>/`。保留旧版本，不运行旧初始化器重置进度。

## 六步执行

### 1. 生成选题

让 `youtube-curiosity-stories` 给出一小批可比较候选：标题/核心问题、反常点、可展开的新发现、证据线索。已有选择直接进入下一步；用户让自行选定时，按好奇心、材料可信度和能否持续展开选一项，记录理由，不空等确认。

### 2. 根据选题生成文案

由文案技能完成研究与完整正文，保留用户标题、修改和已确定语气。资料备注记录来源、数字基准、条件与不确定性；正文中的关键条件不能在配音或画面中消失。

输出英文口播、对应中文审稿及资料备注；从最终口播提取 `narration.txt`，只含要读出的文字。标题、来源链接、编辑说明不送入 TTS，除非它们本来就需要被读出。已定稿只做制作，不擅自润色。

### 3. 根据文案生成配音

优先使用用户指定的最终音频。新配音继承已确认声线、语速、语言和预算；未指定英文声线可使用Edge TTS 路线 `en-US-BrianNeural`、`+0%`，它是联网服务，实际可用性需当次检查。首次定声可先提供短样；用户已允许直接使用默认声线时直接继续。

按 [配音](references/narration.md) 使用可续作脚本，保存全文、分段文本、原生时间数据及参数。校验全文覆盖、文件解码、实际时长，抽听发音和拼接处。不得把已提交任务当成已生成音频，也不因免费路线失败自行转付费服务。

### 4. 根据文案与配音生成带时间戳的画面脚本

对最终音频建立时间依据：优先核验原生逐词时间；没有则对最终文件转写/强制对齐并核对原稿。估时文件标为 `estimated`，不能冒充音频对齐。记录音频 SHA256，保证分镜对应这一版配音。

应用画面技能：根据语义和约两秒一次明显变化的观看节奏划镜；不是每两秒硬切，也不是一句话一镜。已有认可时码保持不变。首镜从 0 开始，连续无重叠覆盖到真实配音结束，片头片尾静音也安排画面。

每镜包含时码、原文片段、主体、景别、动作与构图、主次色块、人物作用、允许短文字、事实及连续性条件、相对上一镜的主要变化。先审相邻 3–5 镜的内容推进，再交下游，字段见 [产物约定](references/contracts.md)。

### 5. 调用画面技能生成画面

沿用 [youtube-ms-paint-images](../youtube-ms-paint-images/SKILL.md) 的粗糙 MS Paint、白底、鲜艳平涂、横屏画面语言；本期用户指定其他风格时以当前要求为准。每个时间点生成一张独立图，不用拼图代替多镜。

新视觉方向先用代表镜头校准；本项目已有认可样图直接复用，仓库展示样图不代表新用户已认可。实际生成遵循当前工具及可用 `imagegen` 指引，内置工具可用时逐帧生成；参考图先查看，区分风格/角色参考和编辑目标，不自行换供应商或代码绘图。

每次成功立即保存图片和逐帧记录，包括实际提示词、参考图、真实尺寸、SHA256、审核状态。小批次报告实际保存量和下一段内容；中断或结果未知时先核对文件与回收结果，只补缺失或未通过项。不要默认启动子代理。

逐张检查，再按相邻 3–5 镜连看动作、角色连续性、构图变化与信息准确性。结构校验不能代替视觉检查。原生图片仅接近 16:9 时如实记录，成片阶段等比补白。

### 6. 合成最终视频

按 [合成](references/rendering.md) 读取当前分镜和已通过图片。普通静态图片加旁白直接用 FFmpeg；默认静态硬切、连续旁白，1920×1080、30fps、H.264/AAC、yuv420p。未要求不加音乐、字幕或全图缩放。

切图不是切音频：旁白整条保留，不每两秒加淡入淡出。切点按绝对时间量化到视频帧，避免逐镜舍入累计漂移。等比补白、不拉伸或误裁主体。

需要真实素材复杂剪辑时才加载 `video-use`；用户要求 ChatCut 可编辑工程时再加载相应 basics、asset-import、verification、export 技能。不要仅因输出 MP4 就强制引入 React、ASR API key 或其他框架。

检查导出文件真实存在、全程解码、音视频时长与编码；抽查头尾、中段、切点和有数字/条件的画面，并试听旁白。技术检查和人工视听检查分别记录。修正后导出新版本并复查受影响部分。

## 完成与交付

按用户范围交付最终 MP4、配音、独立图片、时间戳脚本、合并后的实际提示词、记录和检查报告。明确当前完成阶段、尚缺内容及是否通过视听检查；HTML 预览、联系页、导出已提交都不等于成片完成。没有发布请求时交本地成片，不自行上传发布。
