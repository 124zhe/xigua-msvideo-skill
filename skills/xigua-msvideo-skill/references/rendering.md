# 静态分镜合成与成片验收

## 简单合成

本流程的默认成片是每镜独立图片按时码硬切，配音连续播放；无需 ASR key、React 工程或动画框架。先满足 [分镜接口](contracts.md)，再运行：

```powershell
python "<skill>/scripts/assemble_video.py" --storyboard "outputs/<slug>/storyboard.json" --out "outputs/<slug>/final.mp4" --work "work/<slug>/render"
```

需要 Python 3.10+、ffmpeg、ffprobe。可指定 `--audio`，仍必须匹配分镜的音频 SHA256；可设 `--width 1920 --height 1080 --fps 30`、`--ffmpeg`、`--ffprobe`。已有输出不覆盖，新版另命名。

脚本检查真实音频哈希和时长、连续时间轴、编号、文件名、图片存在且 `image_review_status=passed`，并核对 `image_sha256` 对应已审版本。缺少逐帧审核时先完成审核，不为了运行脚本批量伪标 passed。历史分镜字段不同则生成适配副本，保留原文件与版本关系。

切点从绝对毫秒映射到帧号；末帧向上取整，避免逐镜时长分别四舍五入造成累计漂移。短到量化后为 0 帧的分镜会被拒绝，需调整设计或帧率，不静默丢镜。

每张图片等比缩放并补白，原始图片保持不变；缓存段视频记录源文件哈希、帧数、尺寸、帧率与编码参数。改变一张图只重渲该段，换声音不重生图。视频段流复制串接，完整旁白只编码一次 AAC；不按切图位置分割或淡化声音。最终画幅严格为指定尺寸，原图比例另记。

输出 `<video>.render-report.json` 记录素材哈希、量化切点、编码参数、实际音视频流、时长和全程解码结果。技术验证完成后输出 MP4；失败保留工作段和 `--work` 目录中的 `<video>.failure.json`，不能当成功交付。

## 视听检查

技术验证不能判断图文是否对应。实际播放并抽查头尾、中段、相邻切点及关键数字/条件画面；确认没有空图、黑/白闪、误裁、重复错帧，声音没有漏词、突变、异常静音，末尾没有被截断。普通抽查与完整观看应如实区分。

把检查范围、发现和修复记入单独 `review.md`，技术报告中的 `visual_audio_review: pending` 不自动改为人工通过。针对具体缺陷修复后只重查受影响部分；同一问题修复三次仍未解决则保留可检查结果并说明限制，避免无限渲染。

HTML 同步预览仅辅助审核，不是最终视频。若做本地预览，毫秒比较用 `Math.round(audio.currentTime * 1000)`，HTTP 音频服务应支持 Range，避免切点显示和跳转异常。

## 其他路线

- 用户要求真实素材剪辑、配乐或动画时，按任务读取 `video-use` 或指定制作工具的相关技能；不要把普通静态合成自动升级为复杂工程。
- 用户要求 ChatCut 可编辑工程时，先读当前插件 `chatcut-plugin-basics`，再按需要读取 `asset-import`、`verification`、`export`。保留时间线与资源引用。
- ChatCut 导出须核实任务完成及实际文件；如果用户需要在客户端取文件，明确“导出队列 → 再次下载”的操作。只看到任务提交不能宣称已拿到成片。
